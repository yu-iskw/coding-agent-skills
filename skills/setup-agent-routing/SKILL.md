# Set up agent routing

Set up or edit `.agents/coding-agent-routing.yaml` at the project root. Read the **Policy format** section of the installed `route-coding-task` skill for the file contract and example. Setup saves preferences and ends there.

1. **Load the project policy.** Resolve the repository root and read the existing file when present. On a repeat run, present its targets, precedence, and default. Keep choices outside the requested change, including their order. If the file is invalid, show the problem and ask before repairing it.
2. **Establish available targets.** Ask which CLIs, provider or subscription routes, and models the user can use in this environment. Offer relevant bundled adapters, a trusted custom adapter, or current-session work. If the user wants discovery, use the relevant CLI's documented model picker or non-executing help or status command where available. An installed binary only confirms installation. Treat entitlement as unknown until the user or an authoritative native surface confirms it. Offer native defaults or a verified native automatic model selector. Where the provider matters, confirm the effective inference route as well as the model selector. Record shared routing preferences only. Keep personal entitlement, account details, and secrets in native tooling.
3. **Elicit the user's routing rules.** Ask for the outcomes that should influence selection. Offer a default alone or ordered rules using the user's own objectives. With ordered rules, the user can pick a default or be asked whenever no rule matches. Offer relevant confirmed targets for each rule, including `current-session` where it fits. Users can describe matching conditions in their own words, place exceptions first, and omit the default. Reuse preferences already supplied for this setup. Examples include keeping simple work in the current session, using a configured tool for read-only second opinions, and keeping confidential tasks in the current session. Rules express preferences. Consent to a cross-provider transfer comes from the user request or authorization at delegation time.
4. **Review and save.** Verify the target references, order, and model/provider choices against the policy format. Preview the proposed policy or diff and confirm the path and choices before writing. Validate the saved contents and tell the user how to invoke `route-coding-task` for a dry run. If the user chooses current-session work for everything and has no existing policy, offer to finish without creating the file.
